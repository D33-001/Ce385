โปรเจกต์นี้เป็นการปูพื้นฐานภาษา JavaScript บน Node.js[cite: 2] โดยเน้นย้ำปรัชญาของวิชาคือ **"สถาปัตยกรรมนำ โค้ดตาม"** โค้ดทุกบรรทัดในนี้ถูกเขียนขึ้นภายใต้กฎเหล็กของการเขียน Backend ที่ปลอดภัยและบำรุงรักษาได้ในระยะยาว

## รายละเอียดของแต่ละไฟล์ (Exercise Breakdown)

### 1. `ex1-profile.js` — บัตรแนะนำตัว
*   **เป้าหมาย:** ทำความเข้าใจการประกาศตัวแปรและการจัดการข้อความ
*   **สถาปัตยกรรมและกฎที่ใช้:** 
    *   **ห้ามใช้ `var` เด็ดขาด:** เราใช้ `const` เป็นค่าเริ่มต้นสำหรับข้อมูลที่ไม่เปลี่ยนแปลง และใช้ `let` สำหรับข้อมูลที่ต้องถูกแก้ไข[cite: 2] เพื่อป้องกันบั๊กจากการทะลุบล็อก (Scope)[cite: 2]
    *   **Template Literal:** เลิกใช้การต่อข้อความด้วย `+` และเปลี่ยนมาใช้เครื่องหมาย Backtick (`` ` ``) เพื่อให้อ่านโค้ดง่ายและแทรกตัวแปรด้วย `${...}` ได้โดยตรง[cite: 2]

### 2. `ex2-types.js` — ชนิดข้อมูลและการแปลงค่า
*   **เป้าหมาย:** ทำความเข้าใจพฤติกรรม Data Types ของ JavaScript 
*   **สถาปัตยกรรมและกฎที่ใช้:**
    *   **Dynamic Typing:** JavaScript เปลี่ยนชนิดข้อมูลได้อิสระ เราจึงต้องระวังการนำข้อความ (String) มาคำนวณทางคณิตศาสตร์[cite: 2]
    *   **Strict Equality (`===`):** บังคับใช้ `===` เสมอ เพื่อตรวจสอบทั้ง "ค่า" และ "ชนิดข้อมูล"[cite: 2]
    *   **บั๊กของภาษา:** ไฟล์นี้แสดงตัวอย่างบั๊กคลาสสิก เช่น `typeof null` ได้ค่าเป็น `"object"`[cite: 2] และ `typeof NaN` ได้ค่าเป็น `"number"`[cite: 2]

### 3. `ex3-calculator.js` — เครื่องคิดเลขคะแนน
*   **เป้าหมาย:** การคำนวณคณิตศาสตร์และการจัดการทศนิยม
*   **สถาปัตยกรรมและกฎที่ใช้:**
    *   **No Magic Numbers:** ตัวเลขที่เป็นเกณฑ์ของธุรกิจ (Business Logic) เช่น คะแนนเต็ม 60 ต้องไม่ถูกพิมพ์ฝังไว้ในสูตร แต่ต้องประกาศเป็น `const` ที่ด้านบนสุดของไฟล์เพื่อให้แก้ไขง่ายในอนาคต
    *   **แยกคำนวณ แยกแสดงผล:** ประมวลผลตรรกะทั้งหมดให้เสร็จสิ้นด้วยชนิดข้อมูลแบบ Number ก่อน แล้วจึงค่อยใช้ `.toFixed(2)` ในขั้นตอนสุดท้ายเพื่อแสดงผลเป็น String

### 4. `ex4-grade.js` — ตัดเกรดจากคะแนน
*   **เป้าหมาย:** การควบคุมทิศทาง (Control Flow) และ Data Validation
*   **สถาปัตยกรรมและกฎที่ใช้:**
    *   **กฎเหล็กข้อที่ 1 "อย่าเชื่อไคลเอนต์" (Don't trust the client):** ข้อมูลที่เข้ามาต้องถูกกรอง (Validate) ก่อนเสมอ[cite: 2] หากคะแนนอยู่นอกช่วง 0-100 ระบบจะปฏิเสธการตัดเกรดทันที
    *   **Top-Down Logic:** คำสั่ง `if / else if` ทำงานจากบนลงล่าง จึงต้องเรียงเงื่อนไขจากคะแนนมากไปน้อย[cite: 2]

### 5. `ex5-switch.js` — ระบบสั่งอาหาร
*   **เป้าหมาย:** การใช้คำสั่ง `switch` และ Separation of Concerns
*   **สถาปัตยกรรมและกฎที่ใช้:**
    *   **Strict Matching:** `switch` ใน JS เทียบค่าแบบ `===` เสมอ[cite: 2]
    *   **Intentional Fall-through:** จงใจปล่อยให้เงื่อนไขไหลลงมา (Fall-through) สำหรับเมนูที่ราคาเท่ากัน เพื่อลดการเขียนโค้ดซ้ำ[cite: 2]
    *   **Default Case:** ต้องมี `default` เสมอ เพื่อรับมือกับข้อมูลขยะที่ Client อาจส่งเข้ามา[cite: 2]

### 6. `ex6-login.js` — ระบบตรวจสอบสิทธิ์ (Auth Integration)
*   **เป้าหมาย:** รวมความรู้ทั้งหมดเพื่อสร้างระบบรักษาความปลอดภัยเบื้องต้น
*   **สถาปัตยกรรมและกฎที่ใช้:**
    *   **Order of Execution:** ลำดับการเช็คสำคัญต่อความปลอดภัย ต้องทำ Authentication (ยืนยันตัวตน) ก่อน Authorization (สิทธิ์การใช้งาน) เสมอ[cite: 2]
    *   **Prevention of Information Leakage:** หากรหัสผ่านหรือชื่อผู้ใช้ผิด จะตอบกลับแบบกำกวม เพื่อไม่ให้แฮกเกอร์รู้ว่ามีบัญชีนี้อยู่ในระบบ (เทียบเท่า HTTP Status 401)[cite: 2]
    *   **HTTP Status Mapping:** โค้ดนี้ปูทางไปสู่การตอบกลับแบบ API ในอนาคต (401 = ไม่รู้ว่าใคร, 403 = รู้ว่าใครแต่ห้ามเข้า, 200 = สำเร็จ)[cite: 2]
